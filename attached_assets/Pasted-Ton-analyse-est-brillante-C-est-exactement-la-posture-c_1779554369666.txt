Ton analyse est brillante. C'est exactement la posture critique que j'attends. L'optimisation des coûts (Lazy Loading) et l'expérience utilisateur (hydratation) sont vitales. 

Voici mes arbitrages définitifs pour l'implémentation. Nous partons sur tes recommandations.

[1. LE DÉCLENCHEMENT : LAZY LOADING]
On abandonne l'appel synchronisé dans `/api/scan`. 
Crée une nouvelle route dédiée : `GET /api/alternatives/:barcode?trimester=X`.
Cette route sera appelée UNIQUEMENT quand l'utilisatrice cliquera sur le bouton "Voir les alternatives" dans l'application mobile. 

[2. LA COEXISTENCE MOBILE : OPTION B]
Nous appliquons le pattern "Backend-first + Fallback mobile". 
Le frontend appelle `GET /api/alternatives/...`. 
- Si succès -> On affiche les alternatives du serveur.
- Si hors-ligne ou erreur serveur -> Le mobile retombe sur l'algorithme local existant (`lib/alternatives.ts`). L'écran mobile actuel reste intact.

[3. LA TRAPPE DE SECOURS ET L'UX]
L'exigence du tableau vide `[]` est maintenue. Sur la santé, c'est tolérance zéro.
Si l'IA renvoie `[]`, la route renvoie `[]`. Le frontend mobile a déjà un "Empty state avec formulaire de suggestion", c'est exactement l'UX que nous voulons déclencher dans ce cas précis.

[4. L'HYDRATATION (Format de retour)]
Le backend doit renvoyer le type `AlternativeProduct[]` complet attendu par le mobile, et non de simples codes-barres.
LE FLOW DE LA ROUTE `/api/alternatives` :
1. Recherche du produit d'origine. Extraction de son `search_keyword`.
2. Cache Hit : Vérifie `analysis_cache[trimester].alternatives`. S'il contient des codes-barres, passe directement à l'étape 5.
3. Le Filet + Sniper (Claude Haiku) : Requête Supabase (LIMIT 20) via le keyword -> Appel Claude pour extraire au max 3 codes-barres 100% safe.
4. Mise en cache : Enregistre ces 3 codes-barres dans `analysis_cache[trimester].alternatives`.
5. Hydratation : Fais un `SELECT * FROM products WHERE barcode IN (...)` sur ces codes-barres pour récupérer Name, Brand, Image, etc.
6. Transformation et Renvoi : Formate ces produits en `AlternativeProduct[]` (ajoute les origin_badges, score, etc. selon la logique existante) et renvoie le JSON au mobile.

Tu peux attaquer le backend : contrat OpenAPI, route Express `/api/alternatives`, et la mécanique Filet/Sniper avec Claude Haiku. Affiche-moi le code de la route pour validation avant de toucher au mobile.
