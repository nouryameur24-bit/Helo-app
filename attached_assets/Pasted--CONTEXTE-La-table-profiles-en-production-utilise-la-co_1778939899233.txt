[CONTEXTE]
La table `profiles` en production utilise la colonne `id` (uuid) comme primary key.
Le code de l'app utilise partout `user_id` à la place, ce qui ne correspond
à AUCUNE colonne en production. Conséquence : tous les SELECT, INSERT,
UPDATE et UPSERT sur `profiles` échouent silencieusement ou throw.

L'objectif est de migrer tout le code pour utiliser `id` au lieu de `user_id`
quand il s'agit de la table `profiles` (et SEULEMENT cette table — les autres
tables `scan_history`, `shopping_list`, `community_submissions` utilisent
bien une colonne `user_id` qui existe en prod, NE PAS Y TOUCHER).

⚠️ Important : `user_id` reste utilisé dans le code pour d'autres choses
(variables locales, paramètres de fonction, AsyncStorage key). NE PAS faire
de find-and-replace aveugle. Toucher UNIQUEMENT le contexte des requêtes
Supabase sur la table profiles.

[FICHIERS À MODIFIER]

1. hooks/useProfile.ts
   Deux requêtes `.from('profiles')` utilisent `.eq('user_id', userId)` et
   `.eq('user_id', resolvedLinkedUserId)`. Remplacer par `.eq('id', userId)`
   et `.eq('id', resolvedLinkedUserId)`.

2. components/profile/useAccountActions.ts
   Ligne ~17 : `.eq('user_id', userId)` sur `profiles` → `.eq('id', userId)`
   Ligne ~62 : `.delete().eq('user_id', userId)` sur `profiles` → `.eq('id', userId)`
   Ne PAS toucher la ligne sur `partner_links` (qui utilise pregnant_user_id /
   partner_user_id) et les autres tables.

3. lib/partnerUtils.ts
   Dans `upsertProfile` :
   - L'objet `row` commence avec `{ user_id: params.userId }` → remplacer par
     `{ id: params.userId }`
   - `onConflict: 'user_id'` → `onConflict: 'id'`

   Dans `lookupPartnerCode` :
   - `.select('user_id, first_name')` → `.select('id, first_name')`
   - Le return utilise `data.user_id` → remplacer par `data.id`
   - Garder le shape externe `{ userId: ..., firstName: ... }` (c'est l'API
     publique, ne pas casser les callers).

4. lib/notifications.ts
   Quatre requêtes `.from('profiles')` à corriger :
   - Upsert avec `{ user_id: userId, push_token: ..., updated_at: ... }` et
     `onConflict: 'user_id'` → remplacer la clé `user_id` par `id` dans
     l'objet ET dans onConflict.
   - Deux requêtes `.select('push_token').in('user_id', memberIds)` →
     `.in('id', memberIds)`
   - Une requête `.select('push_token').eq('user_id', params.recipientUserId)` →
     `.eq('id', params.recipientUserId)`

5. components/DisclaimerModal.tsx
   Déjà correct (utilise `.eq('id', user.id)`). NE PAS toucher.
